# 项目实施阶段总览

本表以项目最初约定的八个阶段为准。状态“已完成”表示该阶段的核心代码、测试与文档已落地；后续仍可根据实际业务持续优化。

| 阶段 | 阶段目标 | 关键交付内容 | 当前状态 |
| --- | --- | --- | --- |
| 1. 基础运行安全 | 让 API 能安全、可配置、可预测地运行。 | 端口与运行参数配置；HTTP 读写、空闲和请求超时；优雅关闭；panic recovery；统一 405/错误响应；请求体大小限制与严格 JSON；`go test`、`go vet`、`go test -race` 验证。 | 已完成 |
| 2. 审计与日志可管性 | 让关键业务动作可追溯，运行问题可定位。 | 审计日志及关闭策略；有界队列与固定 worker；请求 ID；状态码、耗时和错误分类日志；服务关闭时等待审计任务完成。 | 已完成 |
| 3. 数据库持久化 | 用真实数据库替换业务内存存储，并保证迁移可控。 | MySQL 连接池与配置；向前数据库迁移；User、Order、Auth Repository；真实库 `user_order_api` 与测试库 `user_order_api_test` 隔离；订单唯一约束与索引；分页、排序与筛选基础。 | 已完成 |
| 4. API 契约化 | 让前后端能够稳定协作和自动化对接。 | `/api/v1` 路由前缀；OpenAPI 文档；稳定错误码；统一金额、时间和分页约定；Postman Collection。 | 已完成 |
| 5. 订单领域完善 | 形成清晰、可重试且权限明确的订单业务规则。 | 订单状态机（待支付、已支付、已取消）；支付与取消接口；客户端 `Idempotency-Key`；重复请求重放；订单归属与管理员跨用户操作规则。 | 已完成 |
| 6. 安全与权限 | 建立生产可用的认证、会话和资源权限基础。 | bcrypt 密码哈希；短期 HS256 JWT Access Token；Refresh Token 哈希持久化、轮换与撤销；注册、登录、刷新、退出、当前用户接口；`user`/`admin` 角色；CORS、限流、TLS 部署约束；认证与权限审计。 | 已完成 |
| 7. 可观测性与运营 | 让服务可监控、可告警、可稳定部署和排障。 | Prometheus 指标与就绪检查；链路追踪；错误率、延迟、队列积压和数据库连接告警；Docker 镜像、环境配置模板与部署运行手册。当前已有健康检查和 API 端到端验收，但尚未完成该阶段。 | 未完成 |
| 8. 按实际瓶颈引入高级组件 | 在确有必要时演进性能与异步能力，避免过早复杂化。 | 高读压场景引入 Redis；审计、通知等异步投递引入消息队列；仅当领域边界、团队协作与独立部署需求成熟后再评估微服务拆分。 | 未完成 |

## 当前进度

- 已完成：6 / 8 个阶段。
- 未完成：阶段 7“可观测性与运营”、阶段 8“按实际瓶颈引入高级组件”。
- 推荐下一步：执行阶段 7，优先补齐 Prometheus 指标、就绪检查、告警基础、Docker 镜像与部署文档；阶段 8 应以实际流量和业务需求为触发条件，不预先引入 Redis 或消息队列。
